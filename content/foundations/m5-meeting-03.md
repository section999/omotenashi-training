Status terms are the most important vocabulary in any handover entry. They tell the incoming shift what has been done and what still needs to happen. Without accurate status labels, every entry is ambiguous.

## The Eight Core Status Terms

| Term | Meaning | When to Use |
|---|---|---|
| <span>対応中<br><em>taiouchuu</em></span> | currently handling | An issue being actively worked on right now |
| <span>対応済み<br><em>taiouzumi</em></span> | already handled | Issue resolved; no further action needed |
| <span>未対応<br><em>mitaiou</em></span> | not yet handled | Request received but no action taken |
| <span>要対応<br><em>youtaiou</em></span> | requires action | Something that must be dealt with by the incoming shift |
| <span>保留<br><em>horyuu</em></span> | on hold | Waiting for decision, information, or approval |
| <span>確認待ち<br><em>kakuninmachi</em></span> | awaiting confirmation | Pending answer from another person or department |
| <span>完了<br><em>kanryou</em></span> | completed | Fully resolved; task is closed |
| <span>依頼あり<br><em>irai ari</em></span> | request received | A request has been logged |

## The Status Lifecycle

Status labels follow a predictable lifecycle. Every incoming request or issue moves through stages:

<span>依頼あり</span> (received) → <span>対応中</span> (in progress) → <span>対応済み</span> / <span>完了</span> (resolved)

When writing a handover entry, choose the label that matches the current stage exactly. Do not use 対応済み for something still in progress, and do not use 対応中 for something fully resolved.

## Blocked Tasks

<span>要対応</span> and <span>確認待ち</span> indicate a task is blocked. When these labels appear, the entry must also name who is responsible for unblocking it. A blocked task without an owner is a task that will not be completed.

## Quiz

**A guest has asked for extra pillows but the request has not been fulfilled yet. Which status label is correct?**

- A. 対応済み
- B. 完了
- C. 未対応
- D. 保留

**Correct Answer:** C

**Explanation:** 未対応 means "not yet handled": a request has been received but no action has been taken. This is the correct label for a request that exists but has not been fulfilled. 対応済み and 完了 both indicate the task is done. 保留 means the task is on hold, which implies a specific reason for the pause. If the task simply has not been started, 未対応 is the precise term.
